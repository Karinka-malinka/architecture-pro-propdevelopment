### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**
|**№**|**Требование**|
| :-: | :- |
| R   | **Надёжность (Reliability)**         |              |
| R1    | Все сервисы должны работать 24/7 и быть доступны в 99,9% случаев |              |
| R2    | В случае сбоев в мобильном приложении должно быть соответствующее оповещение|              |
| P   | **Производительность (Performance)**   |              |
| P1    | Предусмотреть равномерное горизонтальное масштабирование и распределение запросов между серверами, приложениями и ЦОД |              |
|  P2   | Отклик по всем операциям в мобильном приложении должен быть максимально быстрым и занимать миллисекунды|              |
| +R  | **+ Ограничения (Restrictions)**       |              |
|  +R1  | Сервисы "Умного дома" реализованы на платформе партнера и должны предоставлять RESTful или GraphQL API для взаимодействия с системой PropDevelopment |              |
|  +R2  | Партнёр может использовать webhook-уведомления для отправки сообщений в систему PropDevelopment о событиях (например, о попытках доступа) |              |
| +R3   | Новые технологии, если они необходимы, должны быть совместимы с существующими платформами разработки |              |
| +R4    | Новые сервисы должны быть доступны через текущее мобильное приложение, которое используют собственники |              |
| +R5    | Чувствительная информация, передаваемая между сервисами, должна быть защищена механизмом шифрования трафика |              | 
| +R6    | Биометрические данные (например, лица) и номерные знаки автомобилей являются чувствительными данными, которые требуют дополнительной защиты. Необходимо убедиться, что такие данные обрабатываются и хранятся с соблюдением соответствующих стандартов безопасности (например, GDPR, если данные обрабатываются в ЕС). |              | 
| +R7    | Аутентификация и авторизация должны быть по протоколам OAuth 2.0 или JSON Web Tokens (JWT) |              |
